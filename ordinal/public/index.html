Introduction

This space is an archive of my creations, the places I've been, and the experiences that have shaped me. It's a home for reflections, creative experiments, and curated notes.

About Me

I'm Aleph, a software engineer exploring system design, game development, and environmental design. I'm fascinated by emergence, both in how it unfolds within technical systems and how communities form, adapt, and grow as ecosystems around the things they build together.

In my free time, I primarily work with Python and have built a range of tools and small systems. These include Auger, an RSS feed aggregator for the Merveilles Webring Project, and Starlamp, a Django based portfolio management tool. I have also explored C through projects like Apsis, an experiment in building a global metronome for networked music performance using SDL, and Sidg64,an early attempt at a Snowflake style ID generator for PostgreSQL that gave me hands on experience working with libpq-fe. My first website, sudogami, was initially written in C as a fork of Hundred Rabbit's static site generator, before later being migrated to the 11ty JavaScript framework.

Lately, I've been working in S&box, Facepunch's open source game engine, designing and implementing an editor side Local Instance system. The goal is to make level design less repetitious by allowing designers to author a single mesh structure and reuse it across a scene, with changes made to one copy automatically propagating to all others while each placement retains its own transform and local edits. In parallel, I've been developing a game and contributing bug fixes to the engine, using active game development to identify missing features and edge cases in the tooling.

This website is generated by Ordinal, a static site generator I built in Python. Inspired by Wikipedia and other knowledge wikis, it's designed to let relationships between pages emerge naturally over time. Content is written in Markdown and rendered into an interconnected set of pages using simple templates.

Ordinal grew out of years of accumulated journal entries and notes written in a wiki style, moving through tools like Vimwiki, Dendron, and later Obsidian.

Professional Experience

Professionally, I've worked in IT Operations and DevOps within large enterprise environments, focusing on building and maintaining reliable systems at scale. Alongside day to day engineering work, I regularly served as an incident commander during production outages, coordinating response efforts, triaging failures, and guiding systems back to a stable state under real time pressure.

My work has centered on automation and observability, using Python for tooling, Ansible for orchestration, and Prometheus and Grafana to monitor and reason about system health over time. I've implemented and maintained CI/CD pipelines using Jenkins and Bitbucket, deployed containerized services with Docker, Podman, and Kubernetes, and defined infrastructure through Terraform while enforcing infrastructure as code practices with Puppet. Much of this work involved reducing operational friction, improving failure visibility, and making complex systems easier to debug, maintain, and evolve.

Beyond enterprise work, I've contributed to smaller, experimental projects. I maintained web infrastructure and developed asset pipelines for Evil-Algorithm, a VFX studio founded by David Karlack and Leri Greer focused on immersive world design. My role involved building workflows that streamlined integration between third-party tools and internal systems, prioritizing flexibility and iteration over rigid process.

Tools I Use

My tooling reflects the kind of work I do. I primarily use VS Code for programming, with Visual Studio when deeper IDE support is needed. For image editing, I use Affinity Photo as a replacement for Photoshop, and Inkscape for 2D vector work.

Blender is my primary tool for 3D modeling. I've used Substance Designer for texture creation, but I tend to prefer handcrafted textures over purely procedural approaches, especially when visual intent matters more than perfect consistency.

Across all of these tools, I value clarity and control over abstraction. I tend to favor workflows that make structure visible and easy to reason about.

Closing

Over time, I'll be adding more to this site as I go through past entries. Most were written for myself, never with an audience in mind. Some are exceptionally well-written pieces, carefully structured and thought out, while others are scattered thoughts or quick notes. They can be opinionated, and I don't always agree with them anymore, but each one served a purpose at some point.
